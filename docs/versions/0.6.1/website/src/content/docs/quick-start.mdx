---
title: Quick start
description: Create your first Aster workspace and run agents in persistent terminal panes.
---

Start Aster from any project directory:

```bash
aster
```

Aster launches or attaches to your default background session. You do not manage sockets. If you detach, agents keep running.

For the local, SSH, and `aster --remote` workflows, see [How to work with Aster](/docs/how-to-work/).

## Create a workspace

Press `n` to create a workspace. A workspace is a project-level container for tabs, panes, and agents.

Give each active project its own workspace. This keeps agent state readable in the sidebar.

## Run an agent

Start your agent in the root pane.

```bash
pi
```

Aster detects supported agents automatically. The sidebar shows whether each agent is `working`, `blocked`, `done`, or `idle`.

## Keyboard control

Press `ctrl+b` to enter prefix mode, then press an action key.

Common actions:

| Action | Key |
| --- | --- |
| Split right | `prefix+v` |
| Split down | `prefix+minus` |
| New tab | `prefix+c` |
| Next / previous tab | `prefix+n` / `prefix+p` |
| Workspace navigation | `prefix+w` |
| New workspace | `prefix+shift+n` |
| Detach client | `prefix+q` |

After detaching, run `aster` again to reattach to the same session.

## Use the mouse

Aster is mouse-native. You can click panes, tabs, workspaces, and agents; drag borders; select text; and use right-click menus.

## Manage named sessions

Named sessions are separate Aster server namespaces. Use them when you want fully separate runtime state.

```bash
aster session list
aster session attach work
aster session attach side-project
aster session stop work
aster session delete side-project
```

Workspaces are usually enough. Use named sessions when you need isolation between sets of panes, sockets, and persistent state.

## Attach from another machine

Run Aster where the work lives. If the code and credentials are on a server, either SSH there and run Aster like a terminal multiplexer:

```bash
ssh you@server
aster
```

Or attach from your local terminal through SSH:

```bash
aster --remote workbox
aster --remote ssh://you@server:2222
```

For repeat targets, put the host in your SSH config. See [How to work with Aster](/docs/how-to-work/) for the full model.
