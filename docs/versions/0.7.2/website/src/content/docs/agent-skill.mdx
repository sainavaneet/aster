Aster ships a reusable agent skill file at [`SKILL.md`](https://github.com/sainavaneet/aster/blob/master/SKILL.md).

Install that file into any coding agent that supports reusable skills or custom instructions. The skill teaches the agent how to control Aster from inside an Aster pane.

Aster also serves a separate guide at [`github.com/sainavaneet/aster/agent-guide.md`](https://github.com/sainavaneet/aster/agent-guide.md) for a different job: an agent helping a human learn, set up, or troubleshoot Aster. The skill is for an agent operating Aster; the guide is for an agent teaching a human.

## What the skill does

The skill tells an agent to use the `aster` CLI when `ASTER_ENV=1` is set. That means the agent is running inside an Aster-managed pane and can safely talk to the local Aster socket.

With the skill installed, an agent can:

- inspect workspaces, tabs, panes, and neighboring agents
- split panes and run commands without stealing focus
- read pane output and recent logs
- wait for servers, tests, or another agent to finish
- start helper agents in sibling panes

The skill is not a separate app or service. It is a markdown instruction file for agents.

## Install it

Install the skill with `npx skills`:

```bash
npx skills add sainavaneet/aster --skill aster -g
```

The `-g` flag installs it globally for supported agents. Omit `-g` to install it into the current project.

Use the repository copy as the manual fallback and source of truth:

```text
https://github.com/sainavaneet/aster/blob/master/SKILL.md
```

For agents with a skill system, install that file as a skill named `aster`. For agents without a skill system, paste the file into the agent's project or user instructions.

After installation, start the agent inside Aster:

```bash
aster
claude
```

Or use any other coding agent in an Aster pane. The important part is that the agent process runs inside Aster, so `ASTER_ENV=1` is available.

## Safety rule

The skill starts with one guardrail: if `ASTER_ENV=1` is not set, the agent should stop and say it is not running inside an Aster-managed pane.

This prevents an agent outside Aster from trying to control a session it does not own.
