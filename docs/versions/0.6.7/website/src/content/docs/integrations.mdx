Aster detects supported agents automatically. Official integrations can add native session identity for restore, semantic state reports, or both. Claude Code, Codex, and OpenCode state comes from screen detection even when their session identity integrations are installed.

Use integrations when you want native agent session restore, direct state reports from Pi/OMP/Copilot/Hermes/Qoder-style hooks or plugins, or both.

## Install integrations

Open settings inside Aster and use the integrations tab to install recommended integrations for agents found on your `PATH`, or run commands manually:

```bash
aster integration install pi
aster integration install omp
aster integration install claude
aster integration install codex
aster integration install copilot
aster integration install opencode
aster integration install hermes
aster integration install qodercli
```

## Uninstall integrations

```bash
aster integration uninstall pi
aster integration uninstall omp
aster integration uninstall claude
aster integration uninstall codex
aster integration uninstall copilot
aster integration uninstall opencode
aster integration uninstall hermes
aster integration uninstall qodercli
```

## How Aster uses integrations

Aster combines three signals:

| Signal | Purpose |
| --- | --- |
| Process detection | Identifies which pane owns which running process. |
| Screen heuristics | Infers visible native agent state such as `working` or `blocked`. |
| Integration events | Reports native session identity, semantic state, or both depending on the integration. |

Claude Code, Codex, and OpenCode state detection is screen-read first. Their Aster-owned integrations do not author `idle`, `working`, or `blocked` state. Pi, GitHub Copilot CLI, and Hermes Agent report semantic state and session identity. OMP and Qoder CLI report semantic state but do not provide native session restore. Custom socket integrations can report state when they define state that is not visible in the native terminal UI.

Some integrations report native agent session references. Aster uses official session references to resume Claude Code, Codex, GitHub Copilot CLI, Pi, Hermes Agent, and OpenCode panes after an Aster server restart unless `[session] resume_agents_on_restore = false` disables it.

Native session restore requires current Aster integrations: Pi integration version `2`, Claude Code version `5`, Codex version `5`, GitHub Copilot CLI version `1`, OpenCode version `4`, or Hermes Agent version `2`. OMP integration version `2` and Qoder CLI integration version `1` report agent state only. Check installed versions with `aster integration status`.

## Pi

Install the Pi integration:

```bash
aster integration install pi
```

Aster writes the bundled extension to:

```text
~/.pi/agent/extensions/aster-agent-state.ts
```

If `PI_CODING_AGENT_DIR` is set, Aster writes to `$PI_CODING_AGENT_DIR/extensions/aster-agent-state.ts` instead. The extensions directory must already exist. Uninstall removes only that extension file.

## OMP

Install the OMP integration:

```bash
aster integration install omp
```

Aster writes the bundled extension to:

```text
~/.omp/agent/extensions/aster-omp-agent-state.ts
```

If `PI_CODING_AGENT_DIR` is set, Aster writes to `$PI_CODING_AGENT_DIR/extensions/aster-omp-agent-state.ts` instead. The extensions directory must already exist. Uninstall removes only that extension file.

The OMP integration reports `omp` as the agent label through Aster's socket API. It does not require native process detection for the `omp` executable.

## Claude Code

Install the Claude Code hook:

```bash
aster integration install claude
```

The hook reports Claude Code session identity to the local Aster socket on session start. Claude Code state comes from Aster's screen detection.

Aster uses `~/.claude` by default, or `CLAUDE_CONFIG_DIR` when set. The Claude config directory must already exist. Install writes `hooks/aster-agent-state.sh` and updates `settings.json` with Aster hook entries. Uninstall removes the matching hook entries and deletes the hook script.

## Codex

Install the Codex hook:

```bash
aster integration install codex
```

The Codex hook reports session identity through the same local socket API used by other integrations. Codex state comes from Aster's screen detection.

Aster uses `~/.codex` by default, or `CODEX_HOME` when set. The Codex config directory must already exist. Install writes `aster-agent-state.sh`, updates `hooks.json`, and ensures `[features] hooks = true` in `config.toml`. It also removes the deprecated top-level `codex_hooks` flag when present. Uninstall removes Aster entries from `hooks.json` and deletes the hook script, but leaves `config.toml` unchanged.

## GitHub Copilot CLI

Install the GitHub Copilot CLI hook:

```bash
aster integration install copilot
```

Copilot state is reported through the same local socket API used by other integrations.

Aster uses `~/.copilot` by default, or `COPILOT_HOME` when set. The Copilot config directory must already exist. Install writes `hooks/aster-agent-state.sh` and updates `settings.json` with Aster hook entries. The hook maps prompt submission, tool use, post-tool progress after approvals, `ask_user` prompts, `exit_plan_mode` plan review prompts, permission notifications, agent idle notifications, turn stops, and session exits into Aster state. Uninstall removes Aster entries from `settings.json` and deletes the hook script.

After Copilot emits a session-bearing event, Aster can use the reported session id to resume the pane with `copilot --resume=<id>`.

## OpenCode

Install the OpenCode plugin:

```bash
aster integration install opencode
```

Aster writes the plugin to `~/.config/opencode/plugins/aster-agent-state.js`. The OpenCode config directory must already exist. Uninstall removes only that plugin file.

The plugin reports session identity while OpenCode runs inside an Aster pane. After OpenCode emits a session-bearing event, Aster can use the reported session id to resume the pane with `opencode --session <id>`. OpenCode state comes from Aster's screen detection.

## Hermes Agent

Install the Hermes Agent plugin:

```bash
aster integration install hermes
```

Aster writes `~/.hermes/plugins/aster-agent-state/` and enables `aster-agent-state` in `~/.hermes/config.yaml`. The Hermes config directory must already exist. Restart Hermes after installing so the plugin loads. Uninstall removes the plugin directory and removes `aster-agent-state` from `plugins.enabled`.

The plugin reports lifecycle, tool, approval state, and session id while Hermes runs inside an Aster pane. Aster can use the reported session id to resume the pane with `hermes --resume <id>`. Native screen heuristics remain available when the plugin is not installed.

## Qoder CLI

Install the Qoder CLI hook:

```bash
aster integration install qodercli
```

The hook reports semantic state to Aster when Qoder CLI emits lifecycle events.

Aster uses `~/.qoder` by default, or `QODER_CONFIG_DIR` when set. The Qoder config directory must already exist. Install writes `hooks/aster-agent-state.sh` and updates `settings.json` with Aster hook entries. Uninstall removes the matching hook entries and deletes the hook script.

Native screen heuristics remain available when the hook is not installed.

## Custom status labels

Integrations can report a short visual label without changing the semantic state.

For example, an agent can remain semantically `working` while showing `indexing` in the UI.

```bash
aster pane report-agent 1-1 \
  --source custom:docs \
  --agent docs-bot \
  --state working \
  --custom-status indexing
```

User hooks that run next to an Aster-managed integration should use metadata instead of `report-agent`. Metadata changes presentation without taking over the integration's `idle`, `working`, `blocked`, or session restore authority. `--agent` guards the report so it only applies while that authoritative agent is active. `--applies-to-source` guards the report so it only applies while that lifecycle authority source is active. `--display-agent` changes the visible name.

```bash
aster pane report-metadata "$ASTER_PANE_ID" \
  --source user:claude-title \
  --agent claude \
  --title "Refactor auth middleware" \
  --display-agent "Claude: auth" \
  --custom-status "refactor auth" \
  --state-label working="refactoring auth" \
  --ttl-ms 3600000
```

Custom status and state labels are visual-only. Waits, notifications, and workspace rollups still use the semantic state.

## Debug integration state

List known agents:

```bash
aster agent list
```

Read a pane when you need to verify what Aster can see:

```bash
aster pane read 1-1 --source recent --lines 50
```

If integration state looks wrong, first confirm the agent is running inside Aster and that the relevant hook or plugin was installed for the same user account.
