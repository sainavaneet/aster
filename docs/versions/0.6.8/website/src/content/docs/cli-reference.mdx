title: CLI reference
description: Aster commands for sessions, workspaces, tabs, panes, agents, waits, integrations, and status.
---

Aster’s CLI talks to the running server over the same local socket API used by integrations and agents.

Most commands print JSON responses. Use them from scripts when you want deterministic automation.

## Launch and status

```bash
aster                         # launch or attach to the default session
aster --session work          # launch or attach to a named session
aster --remote workbox        # attach through SSH, using local keybindings
aster --remote workbox --remote-keybindings server
aster --remote workbox --handoff
aster --no-session            # single-process escape hatch
aster --default-config        # print default config
aster update                  # download and install from the configured channel
aster update --handoff        # opt into live handoff for supported running servers
aster channel show            # print stable or preview
aster channel set preview     # opt into preview builds
aster channel set stable      # return to stable releases
aster --version               # print version
```

Status commands:

```bash
aster status
aster status server
aster status client
```

## Server

```bash
aster server
aster server stop
aster server reload-config
```

`aster server` runs the headless server explicitly. Use it for supervised or service-style setups. `reload-config` applies reloadable settings without restarting panes.

## Sessions

```bash
aster session list [--json]
aster session attach <name>
aster session stop <name> [--json]
aster session delete <name> [--json]
```

Use `default` as the session name when you need to stop the default session explicitly.

## Workspaces

```bash
aster workspace list
aster workspace create [--cwd PATH] [--label TEXT] [--focus] [--no-focus]
aster workspace get <workspace_id>
aster workspace focus <workspace_id>
aster workspace rename <workspace_id> <label>
aster workspace close <workspace_id>
```

Create a workspace without stealing focus:

```bash
aster workspace create --cwd ~/project --label api --no-focus
```

## Worktrees

```bash
aster worktree list [--workspace ID | --cwd PATH] [--json]
aster worktree create [--workspace ID | --cwd PATH] [--branch NAME] [--base REF] [--path PATH] [--label TEXT] [--focus] [--no-focus] [--json]
aster worktree open [--workspace ID | --cwd PATH] (--path PATH | --branch NAME) [--label TEXT] [--focus] [--no-focus] [--json]
aster worktree remove --workspace ID [--force] [--json]
```

Worktrees are normal Aster workspaces with Git checkout provenance. `worktree create` creates a Git worktree checkout, opens it as a workspace, and groups it with the parent repo workspace. Without `--path`, Aster creates the checkout under `<worktrees.directory>/<repo>/<branch-slug>`.

`workspace close` closes Aster state only. `worktree remove` is the explicit checkout deletion path; it runs `git worktree remove`, never deletes the branch, and requires `--force` when Git refuses a dirty checkout.

## Panes

```bash
aster pane list [--workspace <workspace_id>]
aster pane get <pane_id>
aster pane rename <pane_id> <label>|--clear
aster pane split <pane_id> --direction right|down [--cwd PATH] [--focus] [--no-focus]
aster pane close <pane_id>
```

Read output:

```bash
aster pane read <pane_id> [--source visible|recent|recent-unwrapped] [--lines N]
aster pane read <pane_id> --source visible --ansi
aster pane read <pane_id> --source recent-unwrapped --lines 120
```

Send input:

```bash
aster pane send-text <pane_id> <text>
aster pane send-keys <pane_id> <key> [key ...]
aster pane run <pane_id> <command>
```

`pane run` submits text plus Enter atomically. Prefer it over `send-text` plus `send-keys Enter` for commands.

Report agent state from custom hooks:

```bash
aster pane report-agent <pane_id> \
  --source ID \
  --agent LABEL \
  --state idle|working|blocked|unknown \
  [--message TEXT] \
  [--custom-status TEXT] \
  [--seq N] \
  [--agent-session-id ID] \
  [--agent-session-path PATH]
```

`pane get`, `pane list`, `agent get`, and `agent list` include a read-only `agent_session` object when an official integration has reported a native session reference. If no native session reference is stored, the field is omitted.

Those commands include `foreground_cwd` when Aster can resolve the cwd of the foreground process controlling the pane. The existing `cwd` field remains the pane/workspace cwd used for labels and follow-cwd behavior.

Report display-only pane metadata without taking over semantic state:

```bash
aster pane report-metadata <pane_id> \
  --source ID \
  [--agent LABEL] \
  [--applies-to-source ID] \
  [--title TEXT|--clear-title] \
  [--display-agent TEXT|--clear-display-agent] \
  [--custom-status TEXT|--clear-custom-status] \
  [--state-label STATUS=TEXT] \
  [--clear-state-labels] \
  [--seq N] \
  [--ttl-ms N]
```

`STATUS` is one of `idle`, `working`, `blocked`, `done`, or `unknown`. `--agent` is a guard for the authoritative agent label. `--applies-to-source` is a guard for the active lifecycle authority source. Use `--display-agent` to change the visible name.

## Agents

```bash
aster agent list
aster agent get <target>
aster agent read <target> [--source visible|recent|recent-unwrapped] [--lines N] [--format text|ansi] [--ansi]
aster agent send <target> <text>
aster agent rename <target> <name>|--clear
aster agent focus <target>
aster agent wait <target> --status <idle|working|blocked|unknown> [--timeout MS]
aster agent attach <target> [--takeover]
aster agent start <name> [--cwd PATH] [--workspace ID] [--tab ID] [--split right|down] [--focus|--no-focus] -- <argv...>
```

Agent targets can be terminal IDs, unique agent names, detected or reported agent labels, or legacy pane IDs. Names and labels are agent identities. Terminal IDs and legacy pane IDs are low-level escape hatches.

`agent read` reads the resolved terminal stream. `agent send` writes literal text to that stream. `agent get`, `agent focus`, `agent wait`, and `agent attach` require the resolved terminal to have agent identity. `agent rename` can assign that identity.

Use `pane send-text`, `pane send-keys`, `pane run`, and `terminal attach` for ordinary terminals, servers, tests, shells, or low-level terminal control. Use `pane run` when you want to submit a command with Enter.

## Direct terminal attach

```bash
aster terminal attach <terminal_id> [--takeover]
```

Detach from direct attach with `ctrl+b q`. Send literal `ctrl+b` with `ctrl+b ctrl+b`.

## Waits

Wait for output in a pane:

```bash
aster wait output <pane_id> --match <text> [--source visible|recent|recent-unwrapped] [--lines N] [--timeout MS] [--regex] [--raw]
```

Wait for pane agent state:

```bash
aster wait agent-status <pane_id> --status <idle|working|blocked|done|unknown> [--timeout MS]
```

Use `wait output` for normal commands and servers. Use `wait agent-status` for coding agents.

## Read sources

| Source | Meaning |
| --- | --- |
| `visible` | Current rendered screen. Best for UI feedback loops. |
| `recent` | Recent scrollback with terminal wrapping. |
| `recent-unwrapped` | Recent scrollback without soft wrapping. Best for logs. |

## Environment variables

| Variable | Purpose |
| --- | --- |
| `ASTER_CONFIG_PATH` | Override the config file path. |
| `ASTER_SESSION` | Select a named session for CLI commands. |
| `ASTER_SOCKET_PATH` | Low-level socket path override. |
| `ASTER_LOG` | Set log filter, for example `ASTER_LOG=aster=debug`. |
| `ASTER_DISABLE_SOUND` | Disable sound playback even when sound notifications are enabled. |
