---
title: Integrations
description: Install Aster integrations for Pi, Claude Code, Codex, OpenCode, and Hermes Agent.
---

Aster detects supported agents automatically. Integrations make that detection more precise by reporting semantic state directly to Aster.

Use integrations when you want reliable `working`, `blocked`, `idle`, and `done` state from agent hooks or plugins.

## Install integrations

```bash
aster integration install pi
aster integration install claude
aster integration install codex
aster integration install opencode
aster integration install hermes
```

## Uninstall integrations

```bash
aster integration uninstall pi
aster integration uninstall claude
aster integration uninstall codex
aster integration uninstall opencode
aster integration uninstall hermes
```

## How Aster uses integrations

Aster combines three signals:

| Signal | Purpose |
| --- | --- |
| Process detection | Identifies which pane owns which running process. |
| Agent integration events | Reports semantic state such as `working` or `blocked`. |
| Screen heuristics | Fills gaps when hooks are unavailable or incomplete. |

Integrations enrich state reporting. They do not replace process detection.

## Pi

Install the Pi integration:

```bash
aster integration install pi
```

Aster writes the bundled extension to:

```text
~/.pi/agent/extensions/aster-agent-state.ts
```

If `PI_CODING_AGENT_DIR` is set, Aster writes to `$PI_CODING_AGENT_DIR/extensions/aster-agent-state.ts` instead. The extensions directory must already exist. Uninstall removes only that extension file.

## Claude Code

Install the Claude Code hook:

```bash
aster integration install claude
```

The hook reports agent state to the local Aster socket when Claude Code exposes hook events.

Aster uses `~/.claude` by default, or `CLAUDE_CONFIG_DIR` when set. The Claude config directory must already exist. Install writes `hooks/aster-agent-state.sh` and updates `settings.json` with Aster hook entries. Uninstall removes the matching hook entries and deletes the hook script.

## Codex

Install the Codex hook:

```bash
aster integration install codex
```

Codex state is reported through the same local socket API used by other integrations.

Aster uses `~/.codex` by default, or `CODEX_HOME` when set. The Codex config directory must already exist. Install writes `aster-agent-state.sh`, updates `hooks.json`, and ensures `[features] hooks = true` in `config.toml`. It also removes the deprecated top-level `codex_hooks` flag when present. Uninstall removes Aster entries from `hooks.json` and deletes the hook script, but leaves `config.toml` unchanged.

## OpenCode

Install the OpenCode plugin:

```bash
aster integration install opencode
```

Aster writes the plugin to `~/.config/opencode/plugins/aster-agent-state.js`. The OpenCode config directory must already exist. Uninstall removes only that plugin file.

The plugin reports semantic state while OpenCode runs inside an Aster pane.

## Hermes Agent

Install the Hermes Agent plugin:

```bash
aster integration install hermes
```

Aster writes `~/.hermes/plugins/aster-agent-state/` and enables `aster-agent-state` in `~/.hermes/config.yaml`. The Hermes config directory must already exist. Restart Hermes after installing so the plugin loads. Uninstall removes the plugin directory and removes `aster-agent-state` from `plugins.enabled`.

The plugin reports lifecycle, tool, and approval state while Hermes runs inside an Aster pane. Native screen heuristics remain available when the plugin is not installed.

## Custom status labels

Integrations can report a short visual label without changing the semantic state.

For example, an agent can remain semantically `working` while showing `indexing` in the UI.

```bash
aster pane report-agent 1-1 \
  --source custom:docs \
  --agent docs-bot \
  --state working \
  --custom-status indexing
```

Custom status is visual-only. Waits, notifications, and workspace rollups still use the semantic state.

## Debug integration state

List known agents:

```bash
aster agent list
```

Read a pane when you need to verify what Aster can see:

```bash
aster pane read 1-1 --source recent --lines 50
```

If integration state looks wrong, first confirm the agent is running inside Aster and that the relevant hook or plugin was installed for the same user account.
